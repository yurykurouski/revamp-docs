## 2. Почему документация точна

Главный риск API-документации — расхождение с кодом (штраф «Accuracy»). Он закрыт так:

1. **Тела запросов генерируются из кода.** `tools/generate-request-schemas.mjs` переводит Zod-схемы `@revamp/validation` в схемы OpenAPI (`zod-to-json-schema`). API проверяет запрос теми же схемами (`validateBody` / `validateQuery`), поэтому ограничения в документации (длины, перечисления, форматы, `additionalProperties: false` у `.strict()`-схем) — ровно те, что применяет сервер.
2. **Каждый путь написан по файлу маршрута** `apps/api/src/routes/*.ts`: коды ответов — из `AppError`, которые бросает маршрут и его сервис; сообщения в примерах — дословно из кода.
3. **Коды ошибок сверены с источником:** перечисление `ApiErrorCode` в спецификации и таблицы `errors.md` содержат те же 46 кодов, что `API_ERROR_CODES` в `@revamp/shared-types` (проверено скриптом при подготовке).
4. **Публичные маршруты** совпадают со списком в `routes/__tests__/route-auth.spec.ts`, который падает на любом неклассифицированном маршруте.
5. **Спецификация валидна:** `redocly lint` с набором `recommended` проходит без ошибок и предупреждений; этот набор также проверяет каждый пример на соответствие его схеме.

## 3. Архитектура API (обзор)

Подробно — в `guides/concepts.md` (диаграммы Mermaid); коротко:

* **Контекст системы:** дашборд → REST API (Express + Zod) → MongoDB (данные, транзакции на replica set) и Redis (очереди BullMQ) → воркеры (Playwright-аудит, генерация страницы моделью, публикация в MinIO/S3, почта). Отдельно — публичные `/track/*`, которые вызывают почтовые клиенты и опубликованные прототипы.
* **Жизненный цикл запроса:** helmet + CORS + JSON (10 МБ) → `requireAuth` (JWT + роль из базы + scope студии) → `requireWriter` / `requireOwner` → Zod → маршрут → единый `errorHandler`.
* **Жизненный цикл лида:** диаграмма состояний по таблице `LEAD_TRANSITIONS`; единственный вход в отправку — `POST /outreach/{id}/approve` (Human-in-the-Loop).
* **Модули:** Health, Auth, Organization, Invitations, Leads, Audits, MVP, Outreach, Discovery, Tracking — с таблицей «модуль → ресурсы → за что отвечает».

## 4. Продвинутые темы

| Тема из требований | Где описана |
| --- | --- |
| Сложные потоки запросов | `concepts.md`: последовательности «очередь → ответ → опрос», «ожидание воркера» (правка MVP до 420 с), «поставить или откатить» (503 с откатом статуса) |
| Пагинация | `concepts.md › Pagination`: offset, `page`/`limit`, `totalPages`, почему не курсоры, какие списки ограничены по построению |
| Rate limits | `concepts.md › Rate limits`: честно — лимитов нет, есть только задержка отправки писем 15–45 с; что нужно до публичного запуска |
| Аутентификация и авторизация | `authentication.md`: свойства токена, роль из базы на каждом запросе, таблица ролей, изоляция студий (чужая запись = 404), поток приглашения (sequence diagram), заметки безопасности |
| Таксономия ошибок | `errors.md`: контракт `code` / `message` / `details`, реакция клиента по HTTP-классам, все 46 кодов по группам с формой `details` |
| Идемпотентность | `concepts.md › Idempotency`: без `Idempotency-Key`, но каждое действие безопасно повторять благодаря условию в базе (таблица: повтор → результат) |
| Версионирование | `concepts.md › Versioning` + `CHANGELOG.md`: версия в пути `/api/v1`, SemVer спецификации, правила совместимых изменений, удалённые эндпоинты с заменой |

## 6. Известные ограничения

| Ограничение | Влияние | Как закрыть |
| --- | --- | --- |
| Схемы ответов написаны вручную по TypeScript-интерфейсам | Новое поле интерфейса может не попасть в документацию | Генерировать из типов (`ts-json-schema-generator`) |
| Вложенные объекты аудита (`standardsChecks`, `designCritique`, …) описаны как открытые объекты | Их внутренние поля не видны в справочнике | Полная форма — в `database-expertise.md` §4.2; генерация из типов закроет и это |
| Нет contract-тестов и mock-сервера в репозитории | Примеры проверены по схемам, но не по живым ответам | Schemathesis в CI, команда Prism в README |
| Нет опубликованного сайта и общей песочницы | Справочник открывают локально | GitHub Pages вместе с продакшен-развёртыванием (REV-211) |
| Нет rate limiting в самом API | Описано как предупреждение | Лимитер на `/auth/*` до публичного запуска |
